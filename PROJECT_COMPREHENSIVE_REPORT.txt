1. EXECUTIVE SUMMARY & SYSTEM ARCHITECTURE
================================================================================
The AI Smart Institute Management System is an enterprise-grade, multi-tenant 
SaaS management platform designed for educational institutes, coaching academies, 
universities, and vocational centers.

Technology Stack:
- Backend: FastAPI (Python 3.12) + SQLAlchemy ORM + Pydantic + Uvicorn + PyJWT
- Cloud Database: Supabase PostgreSQL (AWS ap-southeast-1 pooler & direct)
- Frontend: React + Vite + Vanilla CSS (No heavy framework dependence)
- Security: HTTP Bearer Token (JWT), Password Hashing (passlib bcrypt), CORS Middleware

Architecture Overview:
The platform operates as a decoupled Single Page Application (SPA) communicating 
with a RESTful FastAPI backend. Multi-tenancy is handled via the 'institute_code' 
attribute attached to institute users, students, faculty, courses, fees, and 
tax invoices.

3. DATABASE SCHEMA & DATA MODELS DOCUMENTATION
================================================================================

1. User (models/user.py)
   - Purpose: Central authentication table storing user login credentials, roles, 
     and active status.
   - Key Columns: id (PK), username (indexed, unique), password (bcrypt hash), 
     role ('admin', 'faculty', 'student'), institute_code, must_change_password, is_active.

2. Student (models/student.py)
   - Purpose: Comprehensive student profile containing personal, academic, parent, 
     and course enrollment details.
   - Key Columns: id (PK), institute_code, registration_id (e.g. ITE-001-STU001), 
     name, email, mobile, address, date_of_birth, gender, parent_name, parent_mobile, 
     parent_email, course, course_duration, course_fee, batch, approval_status.

3. Faculty (models/faculty.py)
   - Purpose: Academic teaching staff directory.
   - Key Columns: id (PK), institute_code, employee_id (e.g. EMP001), name, email, 
     mobile, address, qualification, specialization, department.

4. Course (models/course.py)
   - Purpose: Academic curriculum catalog.
   - Key Columns: id (PK), institute_code, course_code (e.g. CS101), name, 
     description, duration, fees, mode ('Online'/'Offline'/'Both'), total_classes, 
     start_date, end_date, capacity, is_active.

5. CourseApplication (models/course_application.py)
   - Purpose: Course enrollment link between student and course, tracking learning mode 
     and progress percentage.
   - Key Columns: id (PK), student_id, course_id, status ('Approved'), learning_mode, 
     payment_status ('Paid'/'Pending'), payment_method, amount_paid, completion_status 
     (0-100%), completion_date, application_date.

6. Fee (models/fees.py)
   - Purpose: Financial fee transaction ledger.
   - Key Columns: id (PK), institute_code, student_id, amount, payment_date, 
     payment_method, status ('Paid / Successful', 'Pending', 'Failed', 'Cancelled'), 
     receipt_number, transaction_id (UTR Reference), verification_notes, verified_by, 
     verification_date.

7. TaxInvoice (models/tax_invoice.py)
   - Purpose: Official GST Tax Invoice record for legal compliance.
   - Key Columns: id (PK), invoice_number (e.g. INV-20260822-00042), institute_code, 
     student_id, fee_id, application_id, student_name, registration_id, student_email, 
     student_mobile, student_address, course_name, hsn_sac_code ('999293'), 
     subtotal_amount, cgst_rate (9%), cgst_amount, sgst_rate (9%), sgst_amount, 
     total_tax_amount, total_amount, payment_method, transaction_id, payment_date, 
     status ('Paid / Successful'), created_at.

8. Attendance (models/attendance.py)
   - Purpose: Daily attendance logs by student, course, date, and status.

9. Batch (models/batch.py)
   - Purpose: Batch schedules, class timings, assigned faculty, and room numbers.

10. Certificate (models/certificate.py)
    - Purpose: Issued completion certificates with unique certificate numbers and verification tokens.

11. Notice (models/notice.py) & Suggestion (models/suggestion.py)
    - Purpose: Official circular notices and student feedback box with admin reply threads.

4. BACKEND CONTROLLERS & CORE FUNCTIONS DOCUMENTATION
================================================================================

1. Authentication Router (controllers/auth_controller.py)
   - POST /auth/login: Authenticates user credentials via authenticate_user(). 
     Returns JWT token and user payload.
   - POST /auth/register-student: Self-registration endpoint for student onboarding.
   - POST /auth/change-password: Changes password for first-time user logins.

2. Fees & Verification Router (controllers/fees_controller.py)
   - POST /fees/submit-payment: Receives student fee payment along with 12-digit UTR 
     transaction ID. Sets status to 'Pending'.
   - POST /fees/verify: Admin verification endpoint. Sets status to 'Paid / Successful', 
     'Failed', or 'Cancelled'. Automatically triggers create_tax_invoice() on success!
   - GET /fees/verification-list: Returns all transaction records with UTR references 
     for institute admins.
   - GET /fees/{student_id}: Returns fee ledger for student.

3. Tax Invoice Router (controllers/tax_invoice_controller.py)
   - GET /invoices/student/{student_id}: Lists generated GST Tax Invoices for student.
   - GET /invoices/{invoice_id}: Returns full JSON invoice details.
   - GET /invoices/{invoice_id}/html: Renders printable HTML document view complete 
     with GST 18% calculation table and print trigger button (window.print()).

4. Tax Invoice Service Engine (services/tax_invoice_service.py)
   - create_tax_invoice(db, fee_id, transaction_id, verified_by):
     Calculates subtotal and GST breakdown:
       Subtotal = Total Fee / 1.18
       Total Tax = Total Fee - Subtotal
       CGST = Total Tax / 2, SGST = Total Tax - CGST
     Auto-generates unique invoice number: INV-YYYYMMDD-#####.

5. Course Applications Router (controllers/course_application_controller.py)
   - POST /course-applications/: Student course enrollment.
   - GET /course-applications/all: Admin enrollment management list with filters.
   - PATCH /course-applications/{id}/completion: Updates student course progress % (0-100%).
